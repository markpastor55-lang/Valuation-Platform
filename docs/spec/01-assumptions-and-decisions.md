# 01 — Assumptions and decisions

> Status: **Draft for review** · Owner: Product architecture (with the business owner) · Applies to: all spec sections, iteration-1 build and backlog planning

This section records:

1. the decisions the brief (§12) requires before build, with the **default adopted for
   iteration 1** so that build can proceed;
2. the working assumptions that other spec sections rely on; and
3. the open questions that still need an owner's decision.

A default is a reversible working position, not a confirmation. Each decision stays
`Default adopted` until its owner confirms it. Vocabulary (purpose, scope, property-type, role,
lifecycle and audit codes) is as fixed in [00 — Architecture and conventions](00-architecture-and-conventions.md).
Unresolved specialist interpretations carry `[REVIEW: <ROLE>]` tags (00 §6).

### Release phases used in this document

| Phase      | Working definition (the authoritative definition is in `13-backlog.md`)                                    |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| MVP        | First release used on real jobs by a limited internal team, for the MVP report products in D3 only.        |
| Pilot      | More report products and integrations; wider internal use; selected clients invited to the client portal.  |
| Production | Full product set and general use within the firm. Must be reached before any SaaS/white-label change (D1). |

### Decision status values

| Status            | Meaning                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `Default adopted` | Build proceeds on the recommended default. Owner confirmation outstanding.               |
| `Confirmed`       | Owner has confirmed. Record the date and reference (minutes, email, ticket).             |
| `Changed`         | Owner chose another option. Impact assessment linked and affected spec sections updated. |

### D1 — Initial users and licensing model

| Item              | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

| Question          | Who are the initial users, and is the product an internal tool, a multi-tenant SaaS or a white-label product?                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Options           | (a) Internal firm only. (b) Multi-tenant SaaS. (c) White-label for other firms. ### D4 — Valuation calculation scope

| Item              | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Question          | Should the platform do evidence capture only, provide practitioner-controlled calculators, or do full modelling?                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Options           | (a) Evidence capture only. (b) Practitioner-controlled calculators. (c) Full modelling (DCF, feasibility, residual).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Default adopted   | **(b).** MVP calculators: rate per m² (land, improvements, building); adjusted comparable indications (percentage and dollar adjustments, gross and net adjustment totals); gross and net yield; capitalisation of net income as a cross-check; summation as a cross-check (land plus depreciated improvements); and reconciliation with weighting and a written rationale. Every result stores its inputs, units, formula ID and version (e.g. `land.rate_per_m2@1`). An override requires a reason and records `calculation.overridden`. **Not in MVP:** DCF, residual/feasibility and probabilistic modelling. **Pilot:** DCF import or attachment from external tools. The file is attached as evidence and its key outputs (discount rate, terminal yield, present value) are entered with provenance. The platform does not recalculate them. |
| Impact if changed | Option (a) breaks the brief §10 traceability criterion. Option (c) needs model validation and documentation `[REVIEW: API_STANDARDS]` and AASB 13 technique and input disclosures `[REVIEW: ACCOUNTING]`, and greatly enlarges the test scope.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Owner             | `STANDARDS_OWNER` with the product owner                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Needed by         | MVP for the calculator list; Pilot for the DCF import format                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

## 2. Assumptions

| ID   | Assumption                                                                                                                                                                                                                                                                                                                                                           | Rationale                                                                                 | Risk if wrong                                                     | Validation step                                                                                                |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| A-01 | Desktop and kerbside/restricted are inspection **scopes** (`DESKTOP`, `KERBSIDE`, `RESTRICTED`), not purposes.                                                                                                                                                                                                                                                       | Any purpose can be performed at a scope, subject to rules (00 §4).                        | The selection model and field matrix would need restructuring.    | `STANDARDS_OWNER` confirms during field-matrix review (spec 03).                                               |
| A-02 | Mortgage-security valuations are a client template variant of `MARKET_VALUE`.                                                                                                                                                                                                                                                                                        | The basis of value is market value. Lender requirements differ by client, not by purpose. | Lender-specific validations would need their own purpose code.    | Review two lender instruction sets `[REVIEW: API_STANDARDS]`.                                                  |
| A-03 | A `STANDARDS_OWNER` role exists in addition to the brief's seven roles.                                                                                                                                                                                                                                                                                              | The brief requires a nominated standards owner to approve templates and rules.            | Template approval would have no accountable role.                 | Confirm with the business owner (D7).                                                                          |
| A-04 | Financial reporting references **AASB 13** Fair Value Measurement (not "AASB 113"). AASB 13 alignment is configuration, not hard-coded.                                                                                                                                                                                                                              | Correction in the brief §1; G6.                                                           | Incorrect standard cited in reports.                              | `[REVIEW: ACCOUNTING]` before Pilot.                                                                           |
| A-05 | Valuation, inspection, research cut-off and retrospective cut-off dates are calendar dates (`LocalDate`) in the property's jurisdiction. "Today" for date rules is taken in the asset's time zone: the state default (e.g. `Australia/Perth` for WA), overridden by location for Broken Hill (`Australia/Broken_Hill`) and Lord Howe Island (`Australia/Lord_Howe`). | A valuation date is a legal/professional date, not an instant.                            | Off-by-one-day errors in retrospective and "not in future" rules. | Date-logic tests at state boundaries and DST transitions (spec 12).                                            |
| A-06 | Money is AUD stored as integer cents. The domain uses dollars rounded to cents. Rounding of the adopted value (e.g. to the nearest $5,000) is a separate recorded step governed by the template.                                                                                                                                                                     | Exact arithmetic; rounding stays visible in the trace.                                    | Cent drift; rounding hidden inside calculations.                  | Unit tests; `[REVIEW: ACCOUNTING]` for GST rounding.                                                           |
| A-07 | Areas are canonical in m². Inputs in other units keep the original value and unit (e.g. squares, 1 square = 100 ft² = 9.290304 m²).                                                                                                                                                                                                                                  | Plans and older records often use imperial units or squares.                              | Conversion errors in the area schedule.                           | Conversion tests; display of the original unit in the trace.                                                   |
| A-08 | Ratios (yields, cap rates, incentives, adjustments) are stored as decimal fractions (`0.055` = 5.5 %).                                                                                                                                                                                                                                                               | One representation avoids ×100 errors.                                                    | Order-of-magnitude errors.                                        | Input parsing tests ("5.5%" becomes 0.055).                                                                    |
| A-09 | Every timestamp is stored as a UTC instant and displayed in the viewer's time zone with a zone label.                                                                                                                                                                                                                                                                | Unambiguous audit chronology.                                                             | Disputed event ordering.                                          | Audit tests across time zones.                                                                                 |
| A-10 | Records created offline get client-generated UUIDs (v7 preferred). Photos also carry a content hash.                                                                                                                                                                                                                                                                 | Idempotent sync; brief §10 forbids duplicate assets and photos.                           | Duplicates after retry or reinstall.                              | Sync replay tests with dropped acknowledgements.                                                               |
| A-11 | AI suggestions are **never** auto-accepted, whatever their confidence. No setting bypasses the human decision. The AI service may only emit allow-listed suggestion types (room or area class, visible attributes, outline hints). Concealed construction, operational condition, brand, compliance, dimensions and defects are never suggested.                     | Brief §1 and §5; G2.                                                                      | AI-derived facts reach a report without human confirmation.       | Tests assert no accepted fact exists without a human `ai.suggestion_accepted` or `ai.suggestion_edited` event. |
| A-12 | Each job has exactly one responsible valuer. Co-signatories are optional; each signs their own co-signatory statement.                                                                                                                                                                                                                                               | Single point of professional accountability.                                              | Ambiguous accountability on the certification.                    | `[REVIEW: API_STANDARDS]` on co-signing wording.                                                               |
| A-13 | By default the QA reviewer must be a different person from the responsible valuer. A self-approval exception is per job and authorised by a different user holding `qa.self_approval_exception`.                                                                                                                                                                     | Brief §7 step 8; 00 §5.                                                                   | Small offices cannot complete QA.                                 | Confirm the exception policy with `STANDARDS_OWNER` (Q-04).                                                    |
| A-14 | Western Australian family-law matters are generally heard by the Family Court of Western Australia. The court picklist covers both the Federal Circuit and Family Court of Australia (Divisions 1 and 2) and the Family Court of Western Australia. `[REVIEW: FAMILY_LAW]`                                                                                           | WA has its own state family court.                                                        | The expert-report template references the wrong court or rules.   | Legal review before the `FAMILY_LAW` release.                                                                  |
| A-15 | The platform records valuer credentials (API membership, CPV status, state registration where a jurisdiction requires it) as Administrator-entered data with an expiry date. It does not verify them automatically.                                                                                                                                                  | No authorised verification feed is assumed.                                               | Lapsed credentials appear on a certification.                     | Expiry validation; `[REVIEW: API_STANDARDS]` on which credentials are mandatory per jurisdiction.              |
| A-16 | In a portfolio job, purpose and scope are set at job level and can be overridden per asset. Property type and jurisdiction are per asset (jurisdiction derived from the address). | A-17 | Changing the selection never deletes captured data. Values for fields that are no longer required are kept, marked "not required in current selection" and left out of the report. They return if the selection changes back.                                                                                                                                        | Brief §10 ("without losing prior data").                                                  | Data loss or stale data leaking into the report.                  | Selection-change tests (spec 12).                                                                              |
| A-18 | Inspection, photos, documents, sketching, notes, evidence entry, calculations and validation work offline (the domain library runs on device). Certification, QA, issue, allocation and invoice actions are online only.                                                                                                                                             | MFA step-up and server snapshots are needed for those actions.                            | Field staff blocked, or unsafe offline approvals.                 | Offline test matrix per screen (spec 05 §2).                                                                   |
| A-19 | The device store is encrypted (SQLCipher). | A-22 | Each issued report is an immutable version. A change after issue uses `openAmendment` and produces a new report version. ## 4. Change control

| Step   | Rule                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| Raise  | A proposed change to a default or assumption is raised against its ID (D-, A- or Q-) with the reason.       |
| Assess | Product architecture lists the affected spec sections, the code packages and the reviewer tags involved.    |
| Decide | The owner named in the register decides. The status changes to `Confirmed` or `Changed` with a reference.   |
| Apply  | Affected sections are updated in the same change set. The 00 vocabulary changes only through a 00 revision. |
